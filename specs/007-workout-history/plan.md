# Implementation Plan: Workout History

**Branch**: `007-workout-history` | **Date**: 2026-05-14 | **Spec**: `specs/007-workout-history/spec.md`  
**Input**: Feature specification from `/specs/007-workout-history/spec.md`

## Summary

Two read-only screens — History List (`/history`) and Workout Detail (`/workout-detail`) — that surface completed workouts from the existing Rails API. No backend changes required: `GET /api/v1/workouts` and `GET /api/v1/workouts/:id` already return full exercise and set data via `serialize_workout_with_exercises`. The main implementation work is: dark theme token backfill (matching `006-ui-redesign` for trivial merge later), primitive component upgrades (`Screen`, `Card` dark variants), a new `WorkoutHistoryCard` component, two new screens, and a return-type fix on `getWorkouts` from `Workout[]` → `WorkoutDetail[]`.

## Technical Context

**Language/Version**: TypeScript 5.9 strict  
**Primary Dependencies**: RTK Query (existing), expo-linear-gradient (existing), expo-router 6 (existing)

**Performance Goals**: History list renders < 1s for 150+ workouts; FlatList virtualisation handles this natively

**Scale/Scope**: 2 new screens, 1 new component, 1 type fix, 3 primitive upgrades, 2 route registrations
