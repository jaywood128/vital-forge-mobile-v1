# Implementation Plan: Personal Records + Exercise Progress Charts

**Branch**: `011-personal-records-progress` | **Date**: 2026-05-19 | **Spec**: [spec.md](./spec.md)

## Summary

Add 1RM-based personal record detection and per-exercise progress charts. PRs are detected client-side by scanning full workout history with the Epley formula. Charts display max weight, estimated 1RM, or session volume over time via a segmented line chart. No backend changes required.

⚠️ **Architecture note**: Client-side PR detection assumes full history is loaded. Migrate to server-side `personal_records` table when pagination is added. See backlog ADR for interview-ready explanation.

## Implementation Order

### Step 1 — Install dependencies
```bash
npx expo install react-native-svg
npx expo install react-native-gifted-charts
```

### Step 2 — Stats functions + unit tests
Build and test in isolation before touching any UI.

**`src/lib/stats/epley.ts`**
```typescript
export function calculateEpley1RM(weight: number, reps: number): number
```
- Returns `weight × (1 + reps / 30)`
- Returns `0` if weight ≤ 0 or reps ≤ 0

**`src/lib/stats/prDetection.ts`**
```typescript
export function detectPRSetIds(workouts: WorkoutDetail[]): Set<number>
```
- Sort workouts by `workout_date` ascending
- Scan chronologically; track running max 1RM per `exercise.id`
- First-ever set for an exercise → skip (no prior history to beat)
- Set whose Epley 1RM > running max → add to result Set, update max
- Skip sets where `weight` is null/0 or `reps` is 0

**`src/lib/stats/exerciseHistory.ts`**
```typescript
export function getExerciseSeries(
  workouts: WorkoutDetail[],
  exerciseId: number,
  metric: 'maxWeight' | '1rm' | 'volume'
): ExerciseSeriesPoint[]

export function getCurrentBests(
  workouts: WorkoutDetail[],
  exerciseId: number
): CurrentBests
```

**Tests** (`__tests__/lib/stats/`): ~80% implemented per constitution testing policy. Remaining ~20% as labelled stubs with plain-English comments.

### Step 3 — PRBadge component
**`src/components/PRBadge.tsx`**

Simple display component. Renders a small 🏆 indicator using theme tokens.

Props:
```typescript
type PRBadgeProps = {
  style?: StyleProp<ViewStyle>;
};
```

No logic inside — parent controls whether to render it at all via `{isPR && <PRBadge />}`.

### Step 4 — PRToast component
**`src/components/PRToast.tsx`**

Slide-down animated banner. Uses React Native's built-in `Animated` API (not Reanimated — avoids v4 compatibility risk for this isolated component).

Props:
```typescript
type PRToastProps = {
  exerciseName: string;
  previous1RM: number;
  current1RM: number;
  onDismiss: () => void;
};
```

Behaviour:
- Absolute-positioned overlay at top of screen
- `Animated.Value` drives `translateY`: slides from -80 to 0 on mount
- `setTimeout(onDismiss, 3000)` auto-dismisses
- Parent sets `prToastState` to `null` in `onDismiss`, unmounting the toast
- Second PR while toast visible: parent replaces `prToastState` — React unmounts old, mounts new (no stacking)

### Step 5 — Wire PR detection into active-workout.tsx

**Where**: inside `handleLog`, after `await promise.unwrap()` succeeds (line ~302).

**New state**:
```typescript
const [prToastState, setPrToastState] = useState<PRToastState>(null);
```

**New hook call** (cached — no extra network request):
```typescript
const { data: allWorkouts = [] } = useGetWorkoutsQuery();
```

**After successful log**:
1. Derive `exerciseId` from workout data using the logged `set.id`
2. Compute PR set IDs from `allWorkouts` + current workout
3. If just-logged set is a PR → set `prToastState`, fire `Haptics.notificationAsync(Success)`
4. Render `<PRBadge />` on set rows where `prSetIds.has(set.id)`
5. Render `<PRToast />` when `prToastState !== null`

### Step 6 — Wire PR badges + navigation into workout-detail.tsx

1. Call `useGetWorkoutsQuery()` at top of component
2. `prSetIds = useMemo(() => detectPRSetIds(allWorkouts), [allWorkouts])`
3. Wrap exercise name `<Text>` in `<Pressable>` → navigates to `/exercise-progress?exerciseId=X&exerciseName=Y`
4. Render `<PRBadge />` next to set rows where `prSetIds.has(set.id)`

Pressable min height must meet `spacing.touchMin = 44`.

### Step 9 — exercise-progress.tsx screen

**Route params** (via `useLocalSearchParams`):
```typescript
{ exerciseId: string, exerciseName: string }
```

**Data flow**:
```typescript
const { data: allWorkouts = [] } = useGetWorkoutsQuery();
const bests   = useMemo(() => getCurrentBests(allWorkouts, Number(exerciseId)), [allWorkouts, exerciseId]);
const series  = useMemo(() => getExerciseSeries(allWorkouts, Number(exerciseId), metric), [allWorkouts, exerciseId, metric]);
```

**Layout** (top to bottom):
1. Deep Navy `LinearGradient` background (`navyDeep` → `navyMid`)
2. Back button (top left, `spacing.touchMin` height)
3. Header `Card`: exercise name title + `Est 1RM: X lbs` + `Best: Y lbs`
4. Segmented control: `[Max Weight | 1RM | Volume]` — drives `metric` local state
5. `<ExerciseChart data={series} />`
6. Empty state if `series.length === 0`
7. Single-point note if `series.length === 1`: "Log more sessions to see your trend"
